# i18n Feature Summary & Implementation Details

## Overview

This Next.js 16 project includes comprehensive internationalization (i18n) support using `next-intl`, the industry-standard solution for Next.js App Router. The implementation provides full support for multiple locales, including both LTR (Left-to-Right) and RTL (Right-to-Left) languages, with an easy-to-modify configuration API.

## Features & Characteristics

### 1. Default Locale Support and Adaptation
- **Automatic locale detection** from browser's `Accept-Language` header
- **Default locale** accessible without URL prefix (e.g., `/` for Farsi)
- **Fallback mechanism** ensures invalid locales redirect to default locale
- **Seamless routing** with `localePrefix: 'as-needed'` strategy
- **Current default locale**: Farsi (fa) - RTL language

### 2. RTL and LTR Locale Support
- **Automatic direction handling** via `dir` attribute on `<html>` element
- **Locale-specific direction** configured per locale in `i18n/config.ts`
- **CSS utilities** for RTL-specific styling in `globals.css`
- **Layout adaptation** that automatically applies correct text direction

### 3. Easy-to-Modify API
- **Centralized configuration** in `i18n/config.ts`
- **Simple locale addition** by editing a single array
- **Type-safe** locale operations with TypeScript
- **Helper functions** for common locale operations

### 4. Latest Best Practices
- **next-intl** library (recommended for Next.js App Router)
- **Server Components** by default with `getTranslations`
- **Client Components** support with `useTranslations` hook
- **Static rendering optimization** with `setRequestLocale`
- **Type-safe translations** with TypeScript
- **Locale-aware navigation** components

## Implementation Details

### 1. Configuration (`i18n/config.ts`)

The heart of the i18n system. All locale configuration is centralized here:

```typescript
export type Locale = {
  code: string;        // Locale code (e.g., 'fa', 'en', 'ar')
  name: string;        // Display name
  dir: 'ltr' | 'rtl';  // Text direction
  flag?: string;       // Optional flag emoji for UI
};

export const locales: Locale[] = [
  {
    code: 'fa',
    name: 'فارسی',
    dir: 'rtl',
    flag: '🇮🇷',
  },
  {
    code: 'en',
    name: 'English',
    dir: 'ltr',
    flag: '🇺🇸',
  },
];

export const defaultLocale: string = 'fa';
```

**Key Functions:**
- `getLocaleConfig(locale)` - Get locale configuration
- `isRTL(locale)` - Check if locale is RTL
- `getLocaleCodes()` - Get all locale codes
- `isValidLocale(locale)` - Validate locale code

### 2. Routing (`i18n/routing.ts`)

Configures how locales are handled in URLs:

```typescript
export const routing = defineRouting({
  locales: getLocaleCodes(),
  defaultLocale: defaultLocale,
  localePrefix: 'as-needed', // Default locale has no prefix
});
```

**Navigation Helpers:**
- `Link` - Locale-aware link component
- `redirect` - Locale-aware redirect
- `usePathname` - Get current pathname
- `useRouter` - Locale-aware router

### 3. Middleware (`middleware.ts`)

Handles locale detection and routing on every request:

- Detects locale from `Accept-Language` header
- Redirects to appropriate locale
- Sets locale cookies
- Excludes static files and API routes

### 4. Request Configuration (`i18n/request.ts`)

Configures how next-intl loads translations:

- Loads messages from `messages/[locale].json`
- Validates locale against available locales
- Falls back to default locale if invalid

### 5. Layout Implementation (`app/[locale]/layout.tsx`)

The locale-specific layout that:

- Validates locale parameter
- Sets `dir` attribute for RTL/LTR support
- Sets `lang` attribute on `<html>` element
- Provides translations via `NextIntlClientProvider`
- Enables static rendering with `setRequestLocale`

### 6. Translation Files (`messages/[locale].json`)

JSON files containing all translations, organized by namespace. Currently available:
- `messages/fa.json` - Farsi translations (default locale, RTL)
- `messages/en.json` - English translations (LTR)

Example structure:

```json
{
  "common": {
    "welcome": "خوش آمدید",
    "hello": "سلام"
  },
  "home": {
    "title": "به Next.js خوش آمدید",
    "description": "با ویرایش صفحه زیر شروع کنید."
  }
}
```

## Usage Examples

### Adding a New Locale

1. **Edit `i18n/config.ts`:**
```typescript
export const locales: Locale[] = [
  { code: 'fa', name: 'فارسی', dir: 'rtl', flag: '🇮🇷' },
  { code: 'en', name: 'English', dir: 'ltr', flag: '🇺🇸' },
  { code: 'ar', name: 'العربية', dir: 'rtl', flag: '🇸🇦' }, // Add this
];
```

2. **Create `messages/ar.json`:**
```json
{
  "common": {
    "welcome": "مرحباً",
    "hello": "أهلاً"
  },
  "home": {
    "title": "مرحباً بك في Next.js",
    "description": "ابدأ بتحرير الملف أدناه."
  }
}
```

3. **Done!** The locale is now available at `/ar` route.

**Note:** The default locale (currently Farsi) is accessible at `/` without a prefix. Other locales are accessible at `/[locale]` (e.g., `/en`, `/ar`).

### Using Translations in Server Components

```typescript
import { getTranslations } from 'next-intl/server';
import { setRequestLocale } from 'next-intl/server';

export default async function MyPage({
  params,
}: {
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  setRequestLocale(locale); // Enable static rendering
  
  const t = await getTranslations('home');
  
  return <h1>{t('title')}</h1>;
}
```

### Using Translations in Client Components

```typescript
'use client';

import { useTranslations } from 'next-intl';

export default function MyComponent() {
  const t = useTranslations('common');
  
  return <p>{t('welcome')}</p>;
}
```

### Locale-Aware Navigation

```typescript
import { Link } from '@/i18n/routing';

export default function Navigation() {
  return (
    <Link href="/about">About</Link> // Automatically includes locale
  );
}
```

### Locale Switching

```typescript
'use client';

import { useRouter, usePathname } from '@/i18n/routing';

export default function LocaleSwitcher() {
  const router = useRouter();
  const pathname = usePathname();
  
  const switchLocale = (newLocale: string) => {
    router.replace(pathname, { locale: newLocale });
  };
  
  return (
    <>
      <button onClick={() => switchLocale('fa')}>فارسی</button>
      <button onClick={() => switchLocale('en')}>English</button>
    </>
  );
}
```

## RTL/LTR Implementation

### Automatic Direction Handling

The layout automatically sets the `dir` attribute:

```typescript
const localeConfig = getLocaleConfig(locale);
return (
  <html lang={locale} dir={localeConfig.dir}>
    {/* ... */}
  </html>
);
```

### CSS Support

RTL-specific styles in `globals.css`:

```css
[dir='rtl'] {
  direction: rtl;
}

[dir='ltr'] {
  direction: ltr;
}

/* RTL-specific adjustments */
[dir='rtl'] .rtl\:text-right {
  text-align: right;
}
```

### Tailwind RTL Support

If using Tailwind, configure RTL plugin for automatic RTL utilities.

## Configuration API

### Changing Default Locale

Edit `i18n/config.ts`:
```typescript
export const defaultLocale: string = 'fa'; // Current: Farsi (RTL)
// Change to 'en' for English, 'ar' for Arabic, etc.
```

### Changing URL Strategy

Edit `i18n/routing.ts`:
```typescript
export const routing = defineRouting({
  localePrefix: 'always', // All locales have prefix, including default
  // or
  localePrefix: 'as-needed', // Default has no prefix (current)
});
```

### Utility Functions (`lib/i18n.ts`)

- `getCurrentLocale(pathname)` - Extract locale from pathname
- `getLocale(locale)` - Get locale configuration
- `isRTL(locale)` - Check if RTL
- `getAvailableLocales()` - Get all locales with config
- `getLocaleName(locale)` - Get locale display name

## Best Practices

1. **Always use `setRequestLocale`** in server components for static rendering
2. **Use `Link` from `@/i18n/routing`** instead of Next.js default `Link`
3. **Organize translations** by feature/page (e.g., `home.title`, `common.welcome`)
4. **Test RTL layouts** when adding RTL locales
5. **Use TypeScript** for type-safe translations
6. **Keep configuration centralized** in `i18n/config.ts`
7. **Validate locales** before using them in components

## Performance Considerations

- **Static rendering** enabled with `setRequestLocale`

## Troubleshooting

### Locale not working?
- Check `i18n/config.ts` has the locale
- Verify `messages/[locale].json` exists
- Ensure `middleware.ts` is in root directory

### RTL not working?
- Verify `dir: 'rtl'` in locale config
- Check browser DevTools for `dir="rtl"` on `<html>`
- Ensure layout is setting `dir` attribute

### Translations not showing?
- Check translation keys match between JSON and component
- Verify correct namespace in `getTranslations`/`useTranslations`
- Ensure JSON file is valid JSON format
